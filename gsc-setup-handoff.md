## TL;DR — the real blocker

The verification *method* was never the risk. The risk is that **most custom domains still
serve the client's OLD website, not our Cloudflare Pages build.** GSC only produces useful
data on a domain that actually serves our build. A verification tag/file in our repo will not
appear at a domain whose DNS still points at the old host.

**Proof used:** the HTTP `server:` header. Cloudflare Pages always responds `server: cloudflare`.
Any `Apache` / `Microsoft-IIS` / `Squarespace` / `openresty` response = NOT our Pages build.

## Two verification routes

- **Option A — DNS TXT "Domain property".** For domains whose DNS is on **Cloudflare**. One TXT
  record per domain. Most robust: covers http/https + www/non-www, survives every rebuild,
  scriptable via the Cloudflare API. Decoupled from the build.
- **Option B — HTML meta tag (token).** For domains on external DNS that still serve our Pages
  build via CNAME. Uses the `GSC_VERIFICATION` template token (already wired — see below).
  A URL-prefix property is exact-match on scheme+host (verify the canonical host).

Avoid the loose `googleXXXX.html` file method: our repo root is NOT served — Cloudflare serves
`dist/` — and a file placed in `dist/` isn't regenerated by the build, so it can silently
disappear and un-verify the site later. The meta-tag token is regenerated on every build.

## Template change already made (v5 template)

Path: `~/sites/martial-arts-template-v5/`

1. `index.html` `<head>`, right after the canonical link, added:
   ```html
   <!-- [IF:GSC_VERIFICATION] --><meta name="google-site-verification" content="[GSC_VERIFICATION]"><!-- [/IF:GSC_VERIFICATION] -->
   ```
2. `client-data.yaml` — added (empty by default):
   ```yaml
   # Google Search Console verification. Paste ONLY the content value from Google's
   # "HTML tag" method (google-site-verification=... ) — not the whole <meta> tag.
   # Leave empty until the custom domain actually serves THIS Cloudflare Pages build.
   GSC_VERIFICATION: ""
   ```

**Verified working:** empty token → tag omitted, no unfilled-token warning; token set →
`<meta name="google-site-verification" content="...">` renders. This regenerates on every
build (survives rebuilds). It lives in the **v5 template only** — existing client repos won't
have it until rebuilt.
